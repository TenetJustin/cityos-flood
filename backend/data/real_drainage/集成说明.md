# 地下排水管网：SWMManywhere 合成 + 深圳开放数据（集成说明）

> 目标：给 CITY OS 深圳全自然灾害指挥中心补上「地下排水管网」数据与图层。
> 合成方法来自用户指定的 **SWMManywhere 0.2.2（帝国理工）**：
> OSM 路网 + NASADEM 30m 高程 + OSM 建筑轮廓 → 任意 bbox 的排水管网模型。

## 一、数据资产（backend/data/real_drainage/）

### 1. SWMManywhere 合成模型（示意性管网，非竣工实测）
| 文件 | 说明 |
|---|---|
| `swmm_core_nodes.geojson` | 70,921 节点（检查井/泵站仓/排放口），含地表高程、管底高程、汇水面积、outfall 标记 |
| `swmm_core_edges.geojson` | 68,357 根管道，含管径、长度、坡度、造价；WGS84 |
| `swmm_core_subcatchments.geojson` | 子汇水区（每分块取面积前 2000） |
| `swmm_core_meta.json` | 分块清单（福田/罗湖/南山 + UTM 带） |
| `swmm_futian_model.inp` | 福田分块完整 SWMM 模型（11,755 管 / 337 排放口 / 9,045 子汇水区） |
| `swmm/sz_luohu_core/.../model_6/model_6.inp` | 罗湖+福田东分块模型（17,635 管） |
| `swmm/sz_nanshan/.../model_4/model_4.inp` | 南山分块模型（39,303 管，UTM 49N） |

覆盖范围：**关内核心区** `[113.88, 22.47, 114.18, 22.57]`（福田+罗湖+南山三个 bbox 合并）。
管径 0.15–3.0 m，总长约 2,159 km。

## 二、后端集成（backend/app/drainagenet.py + main.py）

| 端点 | 说明 |
|---|---|
| `GET /api/drainagenet/network?max_features=&min_diameter_m=` | 合成管道 GeoJSON（可只显示干管 ≥0.5m） |
| `GET /api/drainagenet/nodes?outfalls_only=` | 节点 / 仅排放口 |
| `GET /api/drainagenet/subcatchments?max_features=` | 子汇水区 |
| `GET /api/drainagenet/points` | 真实点位（OSM 检查井 + 泵站/内涝点/运营单位） |
| `GET /api/drainagenet/stats` | 模型+台账统计摘要 |
| `GET /api/drainagenet/registers` | 属性台账 |

## 三、前端集成（frontend/src）

- `api.js`：新增 `getDrainageNetwork / getDrainageNodes / getDrainageSubcatchments / getDrainagePoints / getDrainageNetStats / getDrainageRegisters`。
- `components/RiskMap.jsx`：新增三个工具栏开关——**管网**（合成管道，干管 ≥0.5m 加粗棕色）、**干管**（过滤）、**井/泵/涝点**（真实点位），并附图例与统计脚注。

## 四、复现合成（backend/data/swmm/）

```bash
# 1) 任意 bbox 合成（自动：Overpass 建筑 -> 稳健 NASADEM 下载 -> 管道）
.venv/bin/python -u run_bbox.py sz_nanshan 113.88 22.47 114.00 22.56
# 2) 合并多个 bbox 为 app 数据
.venv/bin/python -u merge_bboxes.py
```

环境要点（记录在案，避免踩坑）：
- **pyswmm 被 stub**（`run_swmm.py`）：本机安全环境 SIGKILL 原生 SWMM 求解器，`run_model` 必须为 false；合成本身不需要求解器。
- pyflwdir/gis_utils/swmmanywhere 共 4 处小补丁（transform 以 tuple 传递、V 体积下限、outfall 过滤、默认 pyflwdir 方法），均在 site-packages 内，见代码注释。
- 南山跨 UTM 49/50 带分界（东经 114°），DEM/建筑重投影 CRS 由 `get_utm_epsg(bbox 西南角)` 动态决定。
- Planetary Computer 的 NASADEM COG 范围读偶发失败 → `fetch_dem.py` 用 curl 全量重试下载后本地裁剪重投影。
