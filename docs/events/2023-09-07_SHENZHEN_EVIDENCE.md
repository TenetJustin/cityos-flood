# 端到端候选样例：深圳 2023 年“9·7”极端特大暴雨

## 选择理由与边界

该事件是当前仓库与公开官方资料交集最多的候选：仓库含 2023-09-04 至 09-08 的
CHIRPS 日尺度派生降雨，深圳气象、水务和应急部门有事件级官方总结。它受台风“海葵”
残余环流、季风和弱冷空气共同影响，但不描述为台风直接登陆事件。

当前状态仅为 `candidate`。没有逐站双时间观测、独立积水深度和 forecast-as-issued
快照，因此不能执行有效的历史技巧回测，也不能作为公众预警证据。

## 明确缺口

| 缺失数据 | `missing_status` | 对端到端验证的影响 |
|---|---|---|
| 逐站分钟/小时雨量及每个版本的 `available_at` | `not_acquired` | 无法构造当时可见的降雨强迫或校验局地峰值 |
| 当时签发的数值/临近预报快照 | `not_acquired` | 无法做 forecast-as-issued 回测 |
| 同事件潮位序列、风暴增水分量及统一高程基准 | `not_acquired` | 无法量化沿海边界贡献 |
| 深圳河及城市河道水位/流量、闸泵实际状态 | `not_acquired` | 无法分离河流顶托、排水和操作影响 |
| 可定位、带时间与测量方法的独立积水深度 | `not_published` | 没有连续水深真值，不能报告水深技巧 |
| 道路、公交、地铁中断与恢复的版本化日志 | `not_acquired` | 不能验证交通影响时序 |
| 居民预警接收、理解、绕行、求助、撤离等样本 | `not_collected` | 不得编造“居民真实反应”或遵从率 |
| 部门逐项命令、执行确认、资产 ID 和开始/结束时间 | `not_acquired` | 官方总结不能替代操作日志，不能训练自动调度 |
| 各源明确再分发许可与保留期限 | `unknown` | 原始资料不能随仓库再发布 |

## 允许的第一阶段链路

1. 用官方资料确认事件窗口、成因和汇总事实。
2. 用 CHIRPS 派生日雨只做事件检索与量级交叉检查，保留 `model_inference` 标签。
3. 将全部缺口作为一等记录写入事件 manifest；不插值生成“观测”。
4. 数据补齐后先做泄漏检查与独立事件冻结，再运行历史回测。
5. 任何居民/部门影响分析在真实记录缺失时只能是 `simulation_scenario`。
