# CityOS 浙江四城 · 交付验收门槛

本文件区分网站功能、模拟演练、真实分析和经过验证的预测。四城范围为宁波、台州、温州、杭州；历史事件包括台风、外围雨带、倒槽及其他有证据的强降雨内涝，不以单一事件替代全范围验证。

截至 2026-10-20，项目处于研究型工作台阶段。下表是交付目标，不是已通过的能力声明。

| 验收门槛 | 必须交付的证据 | 当前状态 |
|---|---|---|
| G1：可用的桌面推演 | 四城可配置多维情景；居民行为图明确为假设；同城比较；可编辑、可下载的预案草案；输入校验和浏览器测试 | 已实现首版；居民流向增加固定天气与人群下的三种响应条件敏感性图并写入草案，但它不是统计可信区间。可选导入未来完整 24 小时 ECMWF 格点降雨作为单一外部驱动，其他条件仍须设置，1 小时峰值不可伪造；仍须用户验收和边界检查 |
| G2：真实数据闭环 | 至少覆盖四城的合法公开台风/降雨/潮位/河网来源；观测与实际可获得时间、单位、空间基准、许可、质量、断流和缺失可追溯；每类来源有稳定性检查 | 机场 METAR、NOAA 历史最佳路径与逐日降雨切片、ECMWF 四城天气模式格点已分层接入；后三者分别为历史记录与模型推断，不是四城城区实时雨量/积水；潮河与点位真值仍缺 |
| G3：历史事件回放 | 每城有可审计事件登记和 as-of 数据切片；独立点位或影响真值；按事件证据等级报告可用于训练/验证的范围 | 已接入 NOAA 近三年四城邻近最佳路径候选和 2021 年 7 月逐日降水证据切片；后者杭州有本地站日值，宁波/台州/温州只有区域参照站，温州本地站缺失。仍只有少量 D 级事件资料，缺当时可获得时间与积水真值，不能做定量回测 |

## G1 首版的验收方式

1. 为四城分别设置台风主体、外围雨带、非台风强降雨或其他降雨，选取 6/12/24/48/72 小时窗口，调整降雨、潮位、河网、排水、人群、预警提前量、道路和避险容量。
2. 输出核查压力及组成、假设居民流向图、三种明确标注条件的响应敏感性图、容量与道路可达缺口；同城情景比较应显示输入和结果差异，不出现未经校准的积水概率或伪造的统计可信区间。
3. 生成的预案草案必须保留全部假设、模型版本、比较对象、证据边界、待核查事项和人工批准关口；可下载为 Markdown，但不自动成为正式预案。
4. 空值、越界值和不可能的降雨峰值应阻止推演；居民路径人数应与输入的假设人群总数一致。
5. 网站桌面与窄屏可读，按钮和图像有可访问名称；浏览器本地存储不可用时给出提示。

## 关键数据依赖

- 省级与四城公开平台：需核验申请方式、许可、空间覆盖和更新频率，目录不是已接入数据。
- NOAA IBTrACS：已经取得并显示近三年历史最佳路径候选；必须补充与城市降雨、潮位、积水及报道的关联验证。路径点发生时间为 UTC，单条路径当时首次公开可获得时间未知，不能用于 as-of 预报回测。
- 气象/水利/排水部门：城区雨量、雷达、潮位和河网实况、积水点真值、地形/管网/泵闸运行记录。缺这些数据，不能将规则演练升格为城市点位预测。
- 应急/交通/社区部门：路网状态、避险容量、资源库存、匿名影响与响应记录。缺这些数据，居民 Agent 与资源方案只能标为假设。

完成技术门槛之后，还须由实际使用方进行场景验收。本站不发布公众预警，不自动改变模型版本或执行封路、转移、泵闸、救援调度。
