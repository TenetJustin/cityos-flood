# CityOS 浙江四城 · 交付验收门槛

本文件区分网站功能、模拟演练、真实分析和经过验证的预测。四城范围为宁波、台州、温州、杭州；历史事件包括台风、外围雨带、倒槽及其他有证据的强降雨内涝，不以单一事件替代全范围验证。

截至 2026-10-20，项目处于研究型工作台阶段。下表是交付目标，不是已通过的能力声明。

| 验收门槛 | 必须交付的证据 | 当前状态 |
|---|---|---|
| G1：可用的桌面推演 | 四城可配置多维情景；居民行为图明确为假设；同城比较；可编辑、可下载的预案草案；输入校验和浏览器测试 | 已实现首版；仍须用户验收和边界检查 |
| G2：真实数据闭环 | 至少覆盖四城的合法公开台风/降雨/潮位/河网来源；观测与实际可获得时间、单位、空间基准、许可、质量、断流和缺失可追溯；每类来源有稳定性检查 | 仅机场 METAR 构建快照已接入；与城区积水无直接对应；其他来源待准入 |
| G3：历史事件回放 | 每城有可审计事件登记和 as-of 数据切片；独立点位或影响真值；按事件证据等级报告可用于训练/验证的范围 | 浙江事件只登记了少量 D 级资料，不能做定量回测 |
| G4：内涝模型 | 每城有点位、地形、排水、潮位与河网边界；0–72 小时等级/概率输出有版本、训练窗口、事件外回测、校准与失效统计 | 未达到；旧五城/深圳实验资产不能直接算浙江模型 |
| G5：影响与建议 | 人口、道路、避险与资源台账合法接入；影响估算有真值验证；候选建议可比较、可追溯、受安全规则约束并需人工批准 | 当前只有假设行为规则和通用核查模板 |
| G6：网站与运行 | 正式数据服务、鉴权与审计、端到端测试、断流降级、移动端检查、持续监控、用户验收 | 静态网站和按小时构建已上线；缺安全后端和正式运行流程 |

## G1 首版的验收方式

1. 为四城分别设置台风主体、外围雨带或非台风强降雨，选取 6/12/24/48/72 小时窗口，调整降雨、潮位、河网、排水、人群、预警提前量、道路和避险容量。
2. 输出核查压力及组成、假设居民流向图、容量与道路可达缺口；同城情景比较应显示输入和结果差异，不出现未经校准的积水概率。
3. 生成的预案草案必须保留全部假设、模型版本、比较对象、证据边界、待核查事项和人工批准关口；可下载为 Markdown，但不自动成为正式预案。
4. 空值、越界值和不可能的降雨峰值应阻止推演；居民路径人数应与输入的假设人群总数一致。
5. 网站桌面与窄屏可读，按钮和图像有可访问名称；浏览器本地存储不可用时给出提示。

## 关键数据依赖

- 省级与四城公开平台：需核验申请方式、许可、空间覆盖和更新频率，目录不是已接入数据。
- 气象/水利/排水部门：城区雨量、雷达、潮位和河网实况、积水点真值、地形/管网/泵闸运行记录。缺这些数据，不能将规则演练升格为城市点位预测。
- 应急/交通/社区部门：路网状态、避险容量、资源库存、匿名影响与响应记录。缺这些数据，居民 Agent 与资源方案只能标为假设。

完成技术门槛之后，还须由实际使用方进行场景验收。本站不发布公众预警，不自动改变模型版本或执行封路、转移、泵闸、救援调度。
