# 浙江省数据开放平台目录核查（只读）

核查日期：2026-10-21（北京时间）
入口：[浙江省数据开放平台数据集目录](https://data.zjzwfw.gov.cn/dopServer/#/dataSetIndex)
范围：宁波、台州、温州、杭州；只查看目录元数据和门户可见的预览样例。没有创建数据应用、订阅、下载原始数据或提交申请。

## 结论

平台目录确认存在多类有价值的候选资料：区县面雨量、小时雨量、河道水位、海洋潮位、易涝点/积水监测、历史涝点、应急响应与避灾场所。它们可用于设计城市数据接入和历史事件工作流，但目前不能据此声称四城已获得可持续的实时数据/API：门户开放标签不等于接口权限，目录更新频率与字段描述也有不一致，单位、坐标参考、高程基准、历史覆盖及复用许可仍需逐数据集确认。

门户标注“无条件开放”仅记录为平台开放属性；本轮没有核验各数据集的完整许可文本、下载规则或 API 授权。标注“受限开放”的目录不用于未授权的公开发布。

## 缺口对应的替代方案（供用户审核）

| 关键缺口 | 可以先交付的替代方案 | 能做/不能做 | 需要用户审核的取舍 |
|---|---|---|---|
| 暂无获批、稳定的四城实时 API | 使用经许可的公开天气预报/观测源生成定时快照；支持人工导入获准 CSV/JSON 并显示来源、更新时间和断流状态。 | 可做“最新可取得资料”的只读态势分析和更新检查；静态 Pages 不能保证连续实时，也不把预报称为城市实测。 | 是否接受先以定时快照＋手工数据导入交付，并在首页明确显示快照时刻/数据延迟。 |
| 城区雨量、潮位、河网与点位积水真值不齐，站点坐标/单位未统一 | 按城市显示已证实的站点/风险点覆盖；对缺城区只给“来源覆盖范围内的降雨/水位趋势”和已登记隐患点，不输出未校准水深。模型路线可先采用 SWMM（有管网/子汇水区数据时）或栅格降雨—地形筛查（仅做相对积水敏感区筛选）。 | 可做站点趋势、阈值核查、静态易涝点分布与数据覆盖图；不能代替城市排水水力模型、街道积水深度或可靠风险概率。 | 是否同意把第一版“易涝点结果”定义为“已登记风险点＋观测/阈值异常”，将水深预测保留为待验证研究功能。 |
| 没有居民实际出行/转移微观样本 | 保留有明确假设输入的居民响应情景图：用户设定受影响人数、预警提前量、出行/服从比例、道路可用率、避险容量及需协助比例；用分流条/流向图显示假设人数，并列出敏感性。若后续有合法匿名区域汇总，再校准比例。 | 可比较“假设条件下”的分流压力；不能预测真实居民行为、个体路线或真实转移人数。 | 是否接受继续使用“居民响应情景/假设分流”而不是“居民行为预测”，直到有匿名真值校准。 |

| 历史事件缺少同期可获得的原始预报、独立积水真值与完整覆盖 | 提供逐条来源的事件时间线/动态地图，仅绘制有坐标的已记录点；其余地图范围明确标为资料缺失。可用雨量/水位/遥感作事件筛查背景，保留它们各自的证据类别。 | 可回放“已知发生了什么及资料何时可得”；不能声称模型回测通过或把代理数据当作积水真值。 | 是否接受先交付证据型历史回放，并把定量技巧评分留到有无泄漏真值事件包之后。 |

这些是替代交付路径，不是本轮已经批准的模型变更。任何新增数值必须由真实获准数据或用户明确的情景假设生成，并保留 `observation`、`historical_record`、`model_inference`、`simulated_scenario`、`missing` 标签。

## 目录检索记录与观察

在门户搜索了“浙江省级区县面雨量小时实况信息”“雨量站”“小时雨量”“河道水位”“潮位”“积水监测”“易涝点”“内涝”“避灾安置场所”“应急响应”“实时雨量信息”。目录还返回若干杭州、温州及浙江其他市县候选项。搜索命中不是数据质量认证；名称相同/相近的省级、市级“回流”记录不应重复计为独立观测。

几个可见的目录差异足以要求接入前做时效检查：一些题名带“实时”但目录更新时间是数月前或一年以上；一些字段称“小时雨量”但更新频率标为半年/每年；一些内涝监测样本的深度或入库时间为空；静态易涝点与事件积水监测混在相似搜索结果里。任何实际状态计算都必须根据逐行 `observed_at`、`available_at`、`retrieved_at`、单位、站点映射和质量码评估，不能用门户更新时间代替观测时间。

## 接入前置条件

1. 对每个拟用数据集获取官方接口文档和使用许可，确认是否需要数据应用、订阅或单独审核；本次没有代表用户提交申请。
2. 获取允许公开样例或获准原始数据，核实完整字段字典、单位、时间语义、CRS/高程基准、空间覆盖、历史起止、更新间隔、质量码、缺失/撤回语义及接口限额。
3. 以宁波的积水点/水位、温州小时雨量、台州历史涝点和响应记录、杭州余杭事件记录形成首轮适配器候选；跨城市指标必须统一语义后才比较。海洋潮位与省级应急避灾资料因受限标记，先等授权。
4. 原始记录分类为 `observation` 或 `historical_record`；公开预报/格点为 `model_inference`；情景计算为 `simulated_scenario`；未取得项保持 `missing`。居民信息只接受合法、脱敏的区域汇总，不采集/推断个人路线。
5. 接入后先做静态只读展示、断流/过期提示和历史回放，再分别评估事件外回测。无后端时 Pages 定时快照不能承诺连续实时服务。

## 不会据此宣称的能力

本次目录核查没有下载或保存原始数据，所以不改变前端实时快照，也不把目录容量解释为样本量/有效观测数。它不证明四城积水覆盖完整、不证明实时 API 已批准、不证明居民反应或应急行动完整，也不构成模型回测、公众预警或自动调度验收。
