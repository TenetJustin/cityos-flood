# CityOS · 浙江台风与城市内涝世界模型

CityOS 面向宁波、台州、温州、杭州四城，组织台风、强降雨、潮位、河网、城市空间和历史事件的证据，支持实时数据分析、情景预演和经过人工复核的决策建议。四城共用数据契约与工作台；地形、排水、潮位边界和模型参数需要分别校准。

[打开 CityOS 浙江工作台](https://tenetjustin.github.io/cityos-flood/) · [查看历史五城原型](docs/LEGACY_FIVE_CITY_README.md)

以下能力以当前验收分支代码为准；GitHub Pages 线上站点在分支合并并成功部署前可能仍显示旧版。

## 当前交付

网站已重构为简洁首页和浙江四城统一工作台。首页提供四城入口和地图；工作台可在城市间切换，并保留当前模块。主要模块包括：

| 模块 | 当前能力 |
|---|---|
| 实时态势 | 展示四城来源状态、城市中心地图、机场公开气象快照和 ECMWF 开放天气模式的四城降雨预报格点；两类数据分别标记，均不等于城区积水 |
| 点位 | 登记点位数据线索；缺少坐标、时序和深度真值时不绘制风险点 |
| 居民影响 | 定义人口、交通、生命线和行为证据层；另提供假设人群的规则分流图，明确不代表真实居民反应 |
| 应急决策 | 提供分城核查建议模板和当前会话内的人工复核清单，不执行调度 |
| 事件库 | 登记历史资料并按证据等级说明回放适用范围；显示 NOAA IBTrACS 邻近最佳路径，以及 2021 年 7 月 NOAA 逐日降雨证据切片；代理站与温州本地站缺失明确标注，均不作为积水真值 |
| 情景预演 | 输入事件、时间窗、降雨峰值、潮位、河网、排水、居民与资源假设；可将 ECMWF 完整未来 24 小时格点降雨作为单一外部输入，1 小时峰值必须人工填写；运行透明规则、可视化行为流向、保存/比较同城情景，并生成保留来源的可编辑预案草案；不称为内涝预测或正式预案 |
| 数据与模型 | 列出开放来源、申请状态、许可和模型状态 |

网站采用深色、细边框、柔和高光和实体感面板，视觉上参考 [Solid Glass](https://github.com/deeplethe/solid-glass) 的材质原则；未复制其组件或代码。

## 数据状态与研究路线

公开快照逐次查询四城机场 METAR，并在发布和展示时核查来源元数据、四站身份、时序、质量字段、单位和明确缺失。2026-10-20 的接口核验返回宁波和杭州报文，台州与温州无记录；后续覆盖状态以页面本轮快照为准。机场点位观测不是城区降雨、潮位、河网或积水数据。历史路径索引从 [NOAA IBTrACS](https://www.ncei.noaa.gov/products/international-best-track-archive) 的近三年 CSV 构建，保留来源哈希、抓取时间、UTC 路径点和 EPSG:4326 坐标；按四城中心 500 km 邻近筛出候选。它是事后最佳路径，单条路径当时实际可获得时间未核实（`available_at: null`），不能作为当时预报或内涝真值。浙江省降水和水库信息、温州台风路径与潮位目录等仍是申请线索；“目录已登记”不等于接口已接入。网站按来源状态显示延迟、缺失和待授权。

ECMWF IFS 开放数据的 `tp` 由同一起报批次的 6/12/24/48/72 小时 GRIB2 提取，经米转毫米后，展示四城中心最近的 0.25° 模式格点累计降雨。推演台只允许导入完整的未来 24 小时窗口，+48/+72 小时窗口按相邻累计值相减，输入保留 0.1 mm 精度；不会自动补造缺失的逐时峰值。快照记录起报、有效、本次取得时刻、格点距离、哈希和 CC BY 4.0 署名；正式发布时间及跨构建首次取得时间未知。已过有效时刻的单项及超过 24 小时的起报隐藏数值。GitHub Pages 构建时按小时尝试更新，失败则生成明确“不可用”状态，不把旧值当新值；构建会将气象快照保留为 90 天 Actions 工件，用于短期审计。调度时间不保证准点，原始 GRIB 尚未长期归档，不能据此宣称已具备跨事件 as-of 回测。这也不是经过验证的城区雨量或内涝预报。

NOAA GHCN-Daily 的 2021 年 7 月 20—28 日切片保留逐站文件哈希、0.1 mm 原单位、日值来源/质量标志和缺失。杭州站有本地日值；宁波、台州、温州仅有定海、大陈岛、瑞安的区域参照值，温州本地站缺失。来源标志 S 为逐时报文推算日降水，NOAA 提醒其可能与真正逐日值显著不同；精确本地累计窗口与当时实际可获得时间未知，不能用于 as-of 回测或代替城区积水真值。

下一阶段依次推进四城数据准入、历史事件证据库、点位等级模型与校准、居民和交通影响评估、资源约束的建议比较，以及按城市和事件分层的回测。使用 `observed_at` 与 `available_at` 区分观测发生时间和数据当时实际可获得时间；历史回测只使用起报时刻之前已经可获得的版本。

[查看交付验收门槛与当前缺口](docs/ZHEJIANG_DELIVERY_GATES.md)。桌面推演的情景和备注只存放于当前浏览器；下载的 Markdown 是预案草案，仍须核对真实证据、回测、安全检查和人工批准。

[查看四城数据准入记录](docs/ZHEJIANG_SOURCE_ADMISSION.md)：公开天气预报、卫星降水、潮位站和省市目录分别核查，尚未接入的来源不计为实时能力。

**当前网站是研究型工作台。** 点位四级概率、真实居民行为、实际应急资源库存与跨城迁移性能尚无合格验证结果，页面不会把模拟值冒充实时观测。公众预警由主管部门发布；系统不自动执行封路、人员转移、泵闸或救援调度。

## 本地运行

需要 Node.js 18+。在仓库根目录运行：

```bash
cd frontend
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/`。前端的静态数据位于 `frontend/public/data/`；本地 FastAPI 后端仍可单独运行研究接口，见[历史原型说明](docs/LEGACY_FIVE_CITY_README.md#快速开始)。

## 构建与验证

```bash
cd frontend
npm test
npm run build
cd ..
python3 tests/test_zhejiang_tracks.py
python3 tests/test_zhejiang_forecast.py
python3 tests/test_zhejiang_historical_rain.py
```

部署前还须以 `VITE_STATIC_PAGES=true VITE_BASE_PATH=/cityos-flood/ npm run build:pages` 构建，再运行 `npm run check:pages`，逐城检查静态深链接和四类证据快照的结构；通过构建检查不等于通过线上端到端验收。

更新历史路径索引：在 `frontend/` 执行 `python3 scripts/build_zhejiang_tracks.py`。脚本从 NOAA 官方端点抓取并限制下载大小；刷新后核对来源时间、路径数量、许可和质量标记，再提交生成的 JSON。

本地刷新 ECMWF 天气预报需要 `pip install -r frontend/requirements-forecast.txt`，然后在 `frontend/` 运行 `python3 scripts/fetch_zhejiang_forecast.py`。依赖只用于读取公开 GRIB；没有来源或读包失败时，网站应显示不可用而非复用旧预报。

更新历史降雨切片可运行 `python3 frontend/scripts/build_zhejiang_historical_rain.py`；它会抓取 NOAA 五个固定站点的原始压缩文件，并仅导出指定日期的降水。新来源标志、站点坐标或时段变更须重新审查，不能直接扩大为城区观测。

GitHub Pages 构建使用 `VITE_STATIC_PAGES=true VITE_BASE_PATH=/cityos-flood/ npm run build:pages`，为四城工作台深链接生成静态入口。GitHub Pages 不运行后端服务，也不会将需要身份验证的官方接口凭据放在浏览器中。仓库原有五城后端与实验模块仍保留，作为方法参考，不直接作为浙江四城已验证模型。

## 使用边界

数据、模型和情景结果须分别标记。每条决策建议都需要来源、适用时间、质量、模型版本和人工复核信息；缺关键证据时，只能提供资料核查与研究建议。CityOS 目前不具备真实城市公众预警或自动调度资格。
